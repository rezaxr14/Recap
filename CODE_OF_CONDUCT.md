# Code of conduct

RECAP is a small technical project. The standard is simple: be respectful, argue about the
work rather than the person, and make it easy for newcomers to participate.

## Expected behaviour

- Be direct and specific. Critique code, data, and claims, not people.
- Assume good faith, but ask for evidence when a claim is not reproducible.
- Respect different levels of experience and different working environments.
- Keep discussions on topic. Move long design debates into an issue or ADR.
- Redact secrets, credentials, and sensitive recorded agent content from issues, pull
  requests, logs, and screenshots.

## Unacceptable behaviour

- Harassment, threats, discrimination, or personal attacks.
- Publishing someone's private information without permission.
- Deliberately submitting secrets, malware, or exploit code to public channels.
- Repeatedly derailing technical discussions after a decision has been made.
- Retaliating against someone who reports a problem in good faith.

## Reporting

Report conduct problems privately to the repository owner through their GitHub profile.
Report security vulnerabilities through the private process in [`SECURITY.md`](SECURITY.md),
not a public issue.

The maintainers will review reports in good faith, keep the reporter informed, and take
proportionate action, which may include a warning, removing content, or blocking an account
from the project spaces they control.
