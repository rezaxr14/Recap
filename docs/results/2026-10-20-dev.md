# Benchmark results - 2026-10-20 (dev split)

This is a deterministic pipeline check, not evidence of real LLM or semantic
retrieval performance. The reference agent is scripted, the embedder is the
local 256-dimensional lexical hashing embedder, and the dev split has only two
tasks. Treat the numbers as a reproducibility and safety baseline.

## Protocol

| Item | Value |
|---|---|
| Command | `recap eval run --split dev` |
| Split | `dev` (2 tasks) |
| Dataset hash | `sha256:5ede1cf20476c8fc20f9e0b8bf5a5a21e7e000bb70e0a0b50c5d9ea6d0959382` |
| Agent | deterministic `reference-agent-v1` |
| Embedder | `recap-hashing-embedding-v1`, 256 dimensions, **not semantic** |
| Embedding cache | Postgres content-addressed cache enabled; the hashing provider reports no token usage (`null`, not zero) |
| Chunker | event-aware `version=2`; `naive_fixed` built side by side |
| Retrieval | real PostgreSQL 17 + Elasticsearch 8.19.3 |
| Reproducibility | four consecutive runs produced identical summaries; `tests/integration/test_benchmark_reproducibility.py` runs two more |

## What the numbers do and do not show

- The safety gap is real and visible at the card level: raw card retrieval ranks a
  version-incompatible memory in every task (`incompatible_selection_rate=1.0`),
  while `outcome_aware` rejects it (`0.0`). This is the policy effect the project
  is built to demonstrate.
- Chunk-level retrieval is scoped to the task's environment fingerprint. This is
  intentional: a chunk compiled for API v1 must not be retrieved for a v2 task.
  As a result the two chunk strategies are both correct on this tiny dev split,
  and the chunk rows' `incompatible_selection_rate=0.0` is a **scoping result,
  not a policy measurement**. Do not read the chunk rows as evidence that
  `outcome_aware_chunk` rejects incompatible memories; the card-level row is the
  policy evidence.
- **The `naive_fixed` vs `event_aware` comparison is currently degenerate.** The
  dataset seeds one memory per environment version, so environment scoping
  leaves one candidate and every chunk baseline succeeds. No claim that
  event-aware chunking beats naive chunking is made from these numbers. A
  meaningful ablation needs multiple same-environment distractor memories and
  paraphrase queries (review item P2-2/P2-3), which are not implemented yet.
- Confidence intervals are not reported here because with two tasks they are
  degenerate. The report JSON contains the raw per-task rows and bootstrap
  fields for the full matrix.
